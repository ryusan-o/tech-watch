Claude Code v2.1.318
概要Claude Code v2.1.318 のチェンジログに、小さな追加が1件入りました。Claude Code が「セッション中に自分で書いたmod(自分のインターフェースや挙動を変える拡張。パネル、ステータスライン、スラッシュコマンド、ツール呼び出しへのフックなど)を有効にしてよいか」を尋ねたとき、その回答の記録が残るようになります。これまでは、有効化の許可を求められて答えても、後から何を許可したかを振り返りにくい状態でした。今回の変更で、許可・拒否の判断履歴を確認できる土台ができたと読めます。公開されている説明は1行のみで、記録の保存先や形式の詳細は原文には書かれていません。
詳細を見る
活用案りゅうさんはCodexとClaude Codeを共有リポジトリで使い、自動化や仕組み化を進める立場なので、「AIが自分の環境を書き換える」場面の監査性が上がる点が効く可能性があります。たとえばClaude Codeに状態表示やフックのmodを作らせて有効化の確認が出たとき、あとから「いつ、何を許可したか」を追えると、挙動が急に変わった際の原因切り分けがしやすくなります。クライアント導入や自走支援で、自分以外の人の環境にmodを入れる場合も、承認の履歴が説明材料になります。使い方としては、まず更新後に mod 作成(plugin-authoring系のスキル)を一度試し、有効化の確認に答えたあと、記録がどこに残るかを確認する流れが考えられます。注意点として、公式の説明が1行のため、記録の場所や内容(許可の対象まで残るのか等)は実機で確かめるまで前提にしない方が安全です。
ターミナルで `claude --version` を実行して 2.1.318 以上か確認し、未更新なら `claude update` を実行します。詳細は https://code.claude.com/docs/en/changelog の v2.1.318 の項目を開いて、記録に関する追記や関連ドキュメントへのリンクがないかを見てください。mod を試すときは、有効化の確認に答えたあとに ~/.claude 配下(C:\Users\kato\.claude)に新しい記録が増えていないかを見ると、保存先の当たりがつきます。
