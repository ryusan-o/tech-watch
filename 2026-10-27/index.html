Claude Code v2.1.311
概要Claude Code v2.1.311 の変更履歴で、self-hosted-runner に2つの新オプション `--hold-idle-file` と `--max-hold-min` が追加された。self-hosted-runner は自前のホスト上でClaude Codeのセッションを動かす仕組み。新オプションは、セッションがアイドルになっても、ホスト側が「まだ動いているプロセスがある」と報告している間はセッションを維持するためのもの。報告にはファイルを使う。`--max-hold-min` は維持する時間の上限(分)を決める。変更履歴の記載は1行で、ファイルの書式や既定値までは書かれていない。
詳細を見る
活用案自前のVPSやPCでClaude Codeを常駐させ、ビルド、スクレイピング、バッチ処理などの長い処理を走らせている場面で効く可能性があります。従来は、Claudeが待機状態に入ると、裏で動いている処理があってもセッションが閉じて、結果を拾えなくなる恐れがありました。たとえば `--hold-idle-file /tmp/busy` を指定し、処理側が動いている間だけそのファイルを置くか更新する運用です。処理が終われば、セッションは通常どおりアイドル終了に戻ると考えられます。`--max-hold-min 120` のように上限も付けておけば、処理が固まっても無期限には居座りません。ただし、りゅうさんのVPS運用が self-hosted-runner を使っているかどうかは、こちらでは確認できていません。使っていなければ今は関係が薄いです。また、ファイルの形式(存在確認か中身か)は公式ドキュメントで確かめてから試す方が安全です。
まず自分の環境で self-hosted-runner を使っているかを確認する。ターミナルで `claude self-hosted-runner --help` を打ち、`--hold-idle-file` と `--max-hold-min` が表示されるか見る。次に https://code.claude.com/docs/en/changelog の v2.1.311 の行を開き、リンク先のドキュメントでファイルの書式と既定値を読む。使っていなければ、何もしなくて構わない。

Anthropic files S-1 with the SEC for proposed initial public offering
概要Anthropicが、米証券取引委員会(SEC)に対しS-1登録届出書を提出したと発表しました。S-1は新規株式公開(IPO)を行う際に米国で提出する登録書類で、IPOに向けた正式な手続きが始まったことを意味します。今回の通知に付いている説明文は空で、公開株数、価格帯、上場時期、上場先といった具体的な条件はここからは確認できません。ただしS-1には通常、財務状況、事業リスク、資金使途、ガバナンスなどが記載されます。そのため、Anthropicの収益構造やコスト構造が公式資料として読める可能性があります。
詳細を見る
活用案りゅうさんの場合、株式投資の話というより、Claude APIやClaude Codeを業務基盤にしているので、供給元の経営の安定性を見る材料として使えるかもしれません。具体的には、公開されたS-1の「Risk Factors」「Business」「Management's Discussion」あたりを読み、価格改定、利用制限、モデル提供方針、計算資源への依存といった記述を拾います。クライアントにAI導入を提案する際にも「ベンダーの財務や継続性をどう見るか」の説明材料になりえます。また特定ベンダー一社に固定しない方針(Codexとの併用)の裏付けとして整理するのも一案です。注意点として、S-1は投資家向けの法的書類で量が膨大です。全文を読み込むと時間を取られやすく、現場の運用が変わる情報とは限らないので、要点だけの確認に留めるのが現実的です。
ブラウザで https://www.anthropic.com/news/s1-sec を開いて発表内容を確認し、リンク先のS-1本文(SEC EDGARで「Anthropic」を検索すると出ます)から「Risk Factors」の章だけを先に目を通してください。見るポイントは、顧客集中度、計算資源の調達先、価格・利用制限に関する記述の3点です。気になった箇所があれば、AI導入提案時のベンダーリスク説明用に数行メモしておくと使えます。
