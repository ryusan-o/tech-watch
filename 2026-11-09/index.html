Claude Code v2.1.319
概要Claude Code v2.1.319 のchangelogで、ターミナル版にMCP tasksのサポートが追加されました。MCPサーバー側がツール呼び出しを「タスク」として実行した場合、Claude Codeはその呼び出しをすぐにバックグラウンドへ移し、完了した時点で結果をClaudeに通知します。これまで長時間かかるMCPツールは、完了まで会話の流れを止めてしまうことがありました。今回の対応で、待たずに次の作業へ進めるようになります。ただしMCPサーバー側がtasksに対応している必要があります。
詳細を見る
活用案効きそうなのは、時間のかかる処理をMCPツール化している場面です。たとえば議事録の文字起こしや、大量データの取り込み、レシピや画像の一括生成などです。tasks対応のMCPサーバーなら、呼び出し直後にバックグラウンドへ回り、完了時に結果が通知されます。その間は別のファイル修正やレビューを進められる可能性があります。使うには、自作MCPサーバーのツールをtasks形式で返す実装にし、Claude Code側は v2.1.319 以上へ更新します。注意点は、既存のMCPサーバーがtasks非対応だと従来どおり待ち時間が発生することです。また、バックグラウンド完了後の結果が会話に差し込まれるため、顧客データや外部API課金を伴う処理では、完了通知を見落とさないよう運用を決めておくのが無難です。
ターミナルで `claude --version` を実行し、2.1.319以上か確認してください。次に https://code.claude.com/docs/en/changelog の v2.1.319 の項目を開き、MCP tasksの記述を読みます。そのうえで、普段使っているMCPサーバーのREADMEに tasks対応の記載があるか探すと、効果が出るサーバーを見分けられます。

GitHub: OpenMontageInc/OpenMontage
概要OpenMontageInc/OpenMontageがGitHubのトレンド入りした。「世界初のオープンソースのエージェント型動画制作システム」を名乗り、12の制作パイプライン、100以上のツール、700以上のエージェントスキル/制作ノウハウのファイルを同梱する。手持ちのAIコーディングアシスタント(Claude Codeなど)を、台本・素材・編集・書き出しまで担う動画制作スタジオとして動かす構成。動画制作の手順をスキルファイルとして分解し、エージェントが順に実行する設計と読み取れる。詳細な対応環境や出力品質はREADMEの確認が必要。
詳細を見る
活用案りゅうさんは普段からClaude Codeを使っているので、これは「動画制作を仕組み化する」素材として相性が良いかもしれません。例えば、うま藻の料理教室やりゅうさんちの紹介を、撮影素材と台本メモを渡して30〜60秒のSNS用ショートに自動編集させる使い方です。SNS戦略やDevLogSNSで、投稿の「やらなきゃ」を減らす実験になり得ます。まず別フォルダにcloneし、README記載のパイプライン一覧から「ショート動画」系を1本だけ、手元の素材で動かすのがおすすめです。また700超のスキルファイルは、自分の動画用スキルを設計する際の分解の参考にもなりそうです。注意点として、外部の画像・音声・動画生成APIを使う場合は課金が発生し得ます。人物の声や顔を扱う場合は権利面もあるため、まず無料のローカル処理だけで試すのが安全です。顧客向け納品に使うのは品質確認後が良いでしょう。
ブラウザで https://github.com/OpenMontageInc/OpenMontage を開き、READMEの「Requirements」「Pipelines」「Quick start」の3節を読む。次に作業用の空フォルダで `git clone https://github.com/OpenMontageInc/OpenMontage` を実行し、スキルファイルの置き場所とライセンス(LICENSE)、必要なAPIキーの有無を確認する。課金が必要なAPIが必須でないかを見てから試す。

GitHub: feder-cr/Jobs_Applier_AI_Agent
概要GitHub Trendingに入った「feder-cr/Jobs_Applier_AI_Agent」は、求人検索から応募までを自動化するオープンソースのAI応募ボットです。説明文には「寝ている間に、履歴書にマッチする求人へ自動応募する」とあります。履歴書や希望条件を読み込んで合う求人を探し、LLMで応募書類や回答欄を埋めて応募します。人手による応募作業を減らす狙いのツールで、AIエージェントが実サイト上でフォーム操作まで担う例として注目されています。ここに書いた以外の細かい仕様(対応サイト、設定ファイル名、必要なAPIキーなど)は、説明文からは確認できません。
詳細を見る
活用案りゅうさんの事業に直結する場面は少ないものの、「ブラウザ上の定型フォーム入力をAIエージェントに任せる」設計の参考になる可能性があります。たとえばクライアント向けに、問い合わせ対応や申請書の転記など「やらなきゃいけない入力作業」を自動化する提案をするとき、このリポジトリのREADMEと構成(プロフィール情報の持たせ方、フォームへの回答生成、人の確認を挟む箇所)を見ると、設計の型を掴めるかもしれません。一方で、求人サイトの多くは自動操作を規約で禁じており、アカウント停止のリスクがあります。応募の質が落ちると相手方の信頼も損なうので、実際に動かすより読んで設計を学ぶ使い方が安全です。履歴書などの個人情報を外部LLM APIへ送る点にも注意が必要です。
ブラウザで https://github.com/feder-cr/Jobs_Applier_AI_Agent を開き、READMEの「Features」「Configuration」付近を読んでください。見る点は、(1)利用するLLMとAPIキーの扱い、(2)プロフィール情報をどんなファイルで渡すか、(3)送信前に人が確認する仕組みの有無、の3つです。動かすのは、必要になってからで十分です。
