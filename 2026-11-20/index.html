Claude Code v2.1.328
概要Claude Code v2.1.328 で、Amazon Bedrock、Google Cloud の Agent Platform、Microsoft Foundry、Claude apps gateway 上の Claude Opus 4.6 と Sonnet 4.6 に auto mode が追加されました。これまで auto mode は Anthropic の直接提供環境が中心でしたが、主要クラウド経由の利用でも使えるようになります。また、権限モードを指定していない対話セッションは、この auto mode で開始されます。毎回の許可確認を減らし、AIが自律的に作業を進める挙動が、既定の起動状態になる変更です。
詳細を見る
活用案効くのは、Bedrock や Foundry 経由で Claude Code を使うクライアント企業に導入支援をする場面です。これまでは許可確認が頻繁に出て、「結局AIに任せきれない」という不満が出やすい部分でした。auto mode が既定になれば、ファイル整理や定型スクリプト作成のような低リスクの作業は、確認なしでテンポよく進められる可能性があります。使い方としては、クラウド経由の環境でセッションを開始し、起動直後の表示がどのモードになっているかを確認します。そのうえで、プロジェクトの settings.json に deny ルールを書き、削除、push、本番設定の変更などを明示的に止める構成が考えられます。注意点は、権限モード未指定のセッションが自動的に auto mode になることです。自分の環境で、これまで確認が出ていた操作が出なくなる可能性があります。既存のリポジトリや顧客環境では、先に deny と allow の設定を見直したほうが安全です。
公式の変更履歴 https://code.claude.com/docs/en/changelog を開き、v2.1.328 の項目と auto mode の説明ページを読んでください。そのうえで、テスト用の空フォルダで claude を起動し、Shift+Tab などで現在の権限モードを確認します。続けて、rm や git push のような操作を試して、確認が出るか、止まるかを見てください。確認後、必要なら settings.json の permissions.deny にルールを追加します。

Claude Code v2.1.329
概要Claude Code v2.1.329 のチェンジログで、信頼ダイアログ(trust dialog)に警告が追加された。フォルダを初めて開いて信頼確認が出る際、そのフォルダのフック(hooks)がどこで宣言されているか(どの設定ファイルに書かれているか)が警告文に明示される。フックは任意のシェルコマンドを自動実行できるため、リポジトリ側の設定にあるフックを知らずに許可してしまうリスクを減らす狙いと読める。今回の説明にはこの1点のみが記載されている。
詳細を見る
活用案第三者のリポジトリやクライアントから受け取ったフォルダをClaude Codeで開く場面で効く可能性があります。たとえばクライアントの共有フォルダ、GitHubで拾ったテンプレート、zipで受け取ったプロジェクトなどです。信頼ダイアログが出たら、警告に書かれた宣言場所(プロジェクトの .claude/settings.json か、ユーザー設定かなど)を読み、プロジェクト側にフックがあれば実際にそのファイルを開いて中のコマンドを確認してから許可する、という運用が考えられます。自分が作ったリポジトリ以外では、確認せずに Yes を押す習慣を避けるだけでも安全性が上がります。AIコンサルとして「クライアントへ導入する時の安全確認手順」の一項目にも使えます。注意点として、警告が出ても中身の安全性を判定してくれるわけではないので、内容の確認自体は人が行う必要があります。
まず `claude --version` でバージョンが v2.1.329 以上か確認し、古ければ更新します。次に、テスト用の空フォルダへ `.claude/settings.json` を作り、無害なフック(例: SessionStart で echo を実行)を書いてから、そのフォルダで claude を起動してみてください。信頼ダイアログに宣言場所が表示されるかを実際に見られます。詳細は https://code.claude.com/docs/en/changelog の v2.1.329 の項を参照してください。
