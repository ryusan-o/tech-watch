Claude Code v2.1.304
概要Claude Code v2.1.304 の changelog に、プラグイン(mod)のフック競合に関する追加が入りました。複数のプラグインが同じイベントにフックを登録していて、先に実行されるプラグインが、あなたのmodのフックを1つスキップした場合、transcript(会話記録)に1行が追加されます。その行には、スキップされたイベント名と、スキップしたプラグイン名が書かれます。これまでは、フックが動かなかった理由が分かりにくい場面がありました。
詳細を見る
活用案フックを使った自動化を組んでいる場面で効く可能性があります。たとえば、ツール実行前後の通知、ログ記録、危険コマンドのブロックなどを複数のプラグインで重ねているとき、「期待したフックが動かない」原因を探す手間が減ります。具体的には、動作がおかしいときに transcript を開き、「どのプラグインが、どのイベントのフックをスキップしたか」を示す行を探します。見つかれば、そのプラグインの設定や実行順を見直す入口になります。また、自作modを配布・共有する場面でも、他のプラグインとの干渉を切り分けやすくなる可能性があります。一方、プラグインやフックを1〜2個しか使っていない環境では、この行が出る機会はほとんどなく、設定を変える必要は薄いです。まずは「フックが効かないときは transcript を見る」と覚えておくだけで十分かもしれません。
公式の changelog(https://code.claude.com/docs/en/changelog)で v2.1.304 の該当項目を確認してください。バージョンは `claude --version` で確認でき、古ければ更新します。フックが効かない症状に出会ったときだけ、transcript 内でイベント名とプラグイン名を示す行を探してください。

GitHub: cathrynlavery/diagram-design
概要cathrynlavery/diagram-design は、Claude Code、Codex、GitHub Copilot、Cursor、Factory Droid、Pi といった複数のAIコーディングエージェント向けに使える「編集的(エディトリアル)な図の作成」スキル/設定集です。44種類の図タイプを備え、出力は単体で完結するHTML+SVGです。影(シャドウ)を使わない端正なデザインを掲げ、Mermaid特有の「それっぽいが野暮ったい図」を避けることを明示しています。GitHubのtrendingに上がっており、AIに図を描かせる際のデザイン品質を揃える狙いのリポジトリです。外部ツールへの依存なくHTMLファイル1つで共有・表示できる点が特徴です。
詳細を見る
活用案提案書やクライアント向け資料で「業務フロー図」「システム構成図」「導入ステップ図」を作る場面で効く可能性があります。たとえばAI業務自動化診断の結果説明や、CRM支援の現状(As-Is)と理想(To-Be)の比較図を、Claude Codeに『この業務フローをdiagram-designの流れ図で出して』と頼み、HTML+SVGで出力→ブラウザ表示またはPDF化して添付する、という使い方が考えられます。Mermaidより見た目の統一感が出やすく、コンサル成果物の質感を上げる助けになりそうです。やり方は、リポジトリをclone(またはスキルとして`.claude/skills`配下に配置)し、READMEの手順で読み込ませる形が一般的です。注意点として、これは外部公開のスキルなので、導入前にSKILL内の指示や同梱スクリプトの中身を確認し、クライアントの機密情報を含む図は生成時に外部送信されない運用にしておくのが安全です。また図が必要な頻度が低いなら、無理に入れず現状のMermaidで十分です。
まず https://github.com/cathrynlavery/diagram-design を開き、READMEの対応44タイプ一覧とサンプル画像を確認する。良さそうなら、検証用の空フォルダにcloneし(`git clone https://github.com/cathrynlavery/diagram-design`)、同梱ファイルに不審なスクリプトがないか目を通したうえで、ダミーの業務フロー(例:予約→確認→請求)を1つ図にして、出来栄えを現行のMermaid出力と見比べる。

GitHub: MadsLorentzen/ai-job-search
概要GitHub Trendingに入ったMadsLorentzen/ai-job-searchは、Claude Code上に構築された転職活動用のAIフレームワークです。求人票の評価、職務経歴書(CV)の応募先別カスタマイズ、カバーレターの作成、面接対策までを一通り扱います。クラウドのサービスではなく「自分のマシンで動く」ことが特徴で、READMEの文言は「Fork it and own it」です。リポジトリをforkして自分用に育てる前提の作りになっています。求人というドメインに、Claude Codeのコマンドやスキルを組み合わせた事例です。
詳細を見る
活用案転職の予定がなければ、そのまま使う場面は少ないと思います。むしろ「Claude Codeで1つの業務フローを、評価→加工→文書化→準備の4工程に分けてforkできる形で配布する」という設計の見本として読む価値があります。たとえばコンサルの案件獲得に置き換えると、「提案依頼や問い合わせの評価(受けるか判断)→先方の業界に合わせた提案書のカスタマイズ→見積・メール文面の作成→商談前の想定問答」という同じ型に当てはまる可能性があります。クライアントに導入標準パッケージとして渡す際も、『forkして自分で育てる』形にすれば、りゅうさんの『やってみせて自走させる』方針と合います。注意点として、職務経歴や応募先の情報は個人情報を含むため、クラウド同期されるフォルダや公開リポジトリには置かない運用が安全です。
ブラウザで https://github.com/MadsLorentzen/ai-job-search を開き、READMEと、.claude/ 配下のコマンド・スキル定義(commands や skills のフォルダ)の構成だけ眺めてください。求人評価の基準をどんなファイルに外出ししているか、CVの元データと出力をどう分けているかの2点を見ると、自分の案件評価フローに流用できるか判断できます。
