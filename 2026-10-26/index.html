Claude Code v2.1.310
概要Claude Code v2.1.310 の変更履歴です。Bedrock・Vertex・Foundry といった外部クラウド経由の構成で、Monitor ツールとプラグインモニターが使えるようになりました。テレメトリや nonessential traffic(必須でない通信)を無効にしている場合も同様に使えます。あわせて、これらの環境では長い foreground の sleep がブロックされるようになりました。Monitor は、バックグラウンドで動くコマンドや条件を監視し、結果が出たときに通知を受け取るためのツールです。従来は使えなかった構成でも、待機を sleep ではなく Monitor で行う運用に揃います。
詳細を見る
活用案効いてくるのは、長いビルドやデプロイ、ログ出力を待つ場面です。foreground で `sleep 300` のように待つと、このバージョンではブロックされることがあります。代わりに Bash を `run_in_background` で起動し、Monitor で完了や特定の出力を待つ形にすると、待っている間も他の作業を進められるかもしれません。たとえば VPS 上のサービスの復旧確認や、議事録自動化・LineBot の処理完了待ちに向いている可能性があります。テレメトリを切っている環境でも使えるので、プライバシー重視の設定のまま運用できます。注意点として、sleep を含む既存のシェルスクリプトや自作の待機ループが、Bedrock などの構成で止められる可能性があります。普段 Anthropic 直結のプランで使っているなら影響は小さいので、まずは自分の環境が対象かを確認するくらいで十分です。
公式の changelog(https://code.claude.com/docs/en/changelog)で v2.1.310 の記載を読み、自分の環境が Bedrock/Vertex/Foundry かテレメトリ無効構成かを確認してください。対象なら、`claude --version` でバージョンを確認し、sleep で待っている手順があれば Monitor に置き換えられるか見てみてください。

MCP: Rosh
概要PulseMCPに「Rosh」というMCPサーバーが掲載された。Roshは平易な英語で記述するプログラミング言語で、このMCPサーバー経由で、インタラクティブなWebアプリ、ゲーム、3Dシーンを作成して公開できるとされる。ClaudeなどMCP対応クライアントから自然言語で指示すると、Rosh言語のコードが生成され、そのまま公開まで進められる構成と読める。掲載ページの説明にあるのは作成と公開の機能のみで、料金体系、公開先、ホスティング条件、認証方式などの詳細は説明文からは分からない。
詳細を見る
活用案りゅうさんの場合、本業の中核というより「軽いデモや体験物を最速で形にする道具」として使える可能性があります。たとえば、うま藻の料理教室やイベント向けに、簡単なクイズ、レシピ診断、3Dで見せる藻の培養イメージなどを、コードを書かずに試作して反応を見る使い方です。クライアント提案でも、AI業務自動化の画面イメージをインタラクティブなモックとして見せれば、説明より早く伝わるかもしれません。進め方は、MCPクライアントにRoshサーバーを追加し、「平易な英語で、3問のうま藻診断ページを作って」と依頼し、出力された画面を確認するだけです。注意点は、作成物が「公開」まで行える点です。公開先や公開範囲が不明なので、顧客情報・個人情報・社内資料は入れず、まず非公開か公開しても問題ない内容でのみ試すのが安全です。
まず https://www.pulsemcp.com/servers/rosh-studio-rosh を開き、インストール方法・公開先・利用条件(料金、認証、公開範囲)を確認する。試すなら、機密情報を含まないダミー題材(例: 3問のうま藻クイズ)で1本だけ作り、公開前にURLの公開範囲を確かめる。

GitHub: alchaincyf/huashu-design
概要GitHub Trendingに入った alchaincyf/huashu-design(Huashu Design 3.0)は、Claude Code・Codex・Cursorなど任意のエージェント上で動く、HTMLネイティブのデザイン用スキルです。エージェントに一言指示するだけで、Webページ、アプリのプロトタイプ、編集可能なPPTX、アニメーション、インフォグラフィックといった『そのまま納品できる』成果物を出力します。特徴は、6つの候補から3つの方向性を選ぶ進め方、サンプル画像付きで84種類あるスタイルライブラリ、使うほど好みを学習する『外観台帳』、デザインの自己点検(デザイン体検)機能です。説明文は中国語が中心ですが、英語の補足もあります。
詳細を見る
活用案提案資料やLPを作る場面で、デザインの方向性決めと手直しの手間を減らせる可能性があります。たとえば、AIコンサルの提案書や『りゅうさんち』『うま藻』の紹介ページを作るときに、まず6案から3方向を出させ、84種のスタイル見本から近いものを選べば、ゼロから指示を書く必要がなくなります。PPTXが編集可能な形で出るなら、クライアントに渡した後に先方が自走して直せる点も、『やってみせて自走させる』方針と相性が良さそうです。外観台帳が機能すれば、WONDAYらしい見た目を毎回言い直さずに済みます。やるなら、使い捨てのフォルダにcloneし、Claude Codeのスキルとして読み込んで、既に作ってある提案資料1本を作り直させて、今のやり方と比べるのが安全です。注意点として、出力の品質は未検証で、既存のbrand-voice.mdの表現と食い違う恐れもあります。また顧客向け資料に使う前には、必ずご自身の目で確認する必要があります。
ブラウザで https://github.com/alchaincyf/huashu-design を開き、READMEのインストール手順(Claude Code向けスキルとして入れる方法)と、84種のスタイル見本の画像を確認してください。良さそうなら、空の作業フォルダで `git clone https://github.com/alchaincyf/huashu-design` を実行し、README記載の手順でスキルとして読み込んで、『うま藻の料理教室の案内LPを作って』のような小さな依頼を1件だけ試します。ライセンス表記も先に確認してください。
