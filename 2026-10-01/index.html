Claude Code v2.1.286
概要Claude Code v2.1.286 の変更履歴に、権限確認(パーミッションプロンプト)の表示改善が入りました。複数の許可リクエストが同時に溜まった場合、プロンプトに「2 of 5」のような件数表示が追加されます。これまでは何件の確認が待っているのか分からないまま、1件ずつ承認を繰り返す必要がありました。今回の変更で、あと何件残っているかが一目で分かります。説明文に書かれている変更はこの1点です。詳細は公式の changelog(https://code.claude.com/docs/en/changelog)に掲載されています。
詳細を見る
活用案効きそうな場面は、サブエージェントや複数ツールが並列に動き、権限確認が一気に溜まる時です。例えば、CodexとClaude Codeを共有リポジトリで使う作業や、複数ファイルの編集とBash実行を含むまとめ作業が該当します。「2 of 5」と出れば、残りが少ないのでこのまま承認するか、多いので中身を確認するかを判断しやすくなります。件数が想定より多い時は、意図しない操作が混ざっていないかを立ち止まって見る合図にもなります。また、毎回出る確認が多いと分かった場合は、読み取り専用コマンドを allowlist に入れる fewer-permission-prompts スキルの出番かもしれません。注意点として、件数が分かっても、承認を流れ作業にしてよいわけではありません。削除や外部送信を伴う操作は、件数に関係なく内容を読んで判断するほうが安全です。
ターミナルで `claude --version` を実行し、v2.1.286 以降か確認します。古ければ `claude update` で更新できます。その後、複数ファイルを並列で編集させる作業を依頼し、権限確認に「N of M」が出るか見てみてください。詳細は https://code.claude.com/docs/en/changelog の v2.1.286 の項にあります。

GitHub: SYSTRAN/faster-whisper
概要SYSTRAN/faster-whisperがGitHubのトレンド入りしている。OpenAIのWhisperを推論エンジンCTranslate2で再実装したもので、説明文は「Faster Whisper transcription with CTranslate2」。CTranslate2はTransformerモデルを高速・省メモリで動かすライブラリで、同じ精度のまま本家Whisperより高速、かつGPUメモリ消費が少ない点が特徴とされる。8bit量子化にも対応し、CPUのみでも実用速度で動かせる。Pythonから WhisperModel を呼ぶだけで文字起こしができ、VAD(無音区間除去)や単語単位のタイムスタンプも扱える。
詳細を見る
活用案議事録の自動生成(MeetingMinutes)で音声認識を使っているので、そこが主な活用場面になる可能性があります。現在はOpenAIのWhisper APIを使っているようで、clients/wonday.yamlのopenai_promptに固有名詞を入れて精度を補っています。faster-whisperをローカルで動かす構成なら、API課金を減らせ、商談音声を外部に送らずに済みます。具体的には WhisperModel("large-v3", device="cpu", compute_type="int8") で読み込み、transcribe(audio, language="ja", vad_filter=True, initial_prompt="ズケヤマセイラ 日高栄祐 濱地心") のように渡すと、固有名詞の誤変換対策(initial_prompt)も今の方式に近い形で再現できます。vad_filter=Trueは無音時のハルシネーション抑制にも効く可能性があります。注意点として、Windows機のCPUだとlarge-v3は長時間会議で処理が重くなるため、最初はmediumやsmall、またはGPUの有無を確認してから比較するのがよさそうです。また、精度はAPI版と同一とは限らないので、既存の議事録数本で並べて確認する必要があります。
まず `pip install faster-whisper` を別の仮想環境で実行し、手元の短い会議音声(5〜10分)で次を試す。`from faster_whisper import WhisperModel; m=WhisperModel('small', device='cpu', compute_type='int8'); segs,_=m.transcribe('sample.mp3', language='ja', vad_filter=True, initial_prompt='ズケヤマセイラ'); print(''.join(s.text for s in segs))`。処理時間と、人名の誤変換が出るかをAPI版の出力と見比べる。READMEの「Usage」と「Benchmark」の節も確認する。

GitHub: eatmoreduck/boss-zhipin-scraper
概要GitHubで話題のリポジトリ「eatmoreduck/boss-zhipin-scraper」は、中国の求人サイトBOSS直聘(Boss Zhipin)の求人データを抓取するツールです。Chrome CDP(Chrome DevTools Protocol)で、実際にログイン済みのブラウザ状態を再利用します。サイト側が使うフォント難読化による反スクレイピング対策を回避し、給与を平文で取得できるとされています。出力はJSONとCSVの2形式です。取得した給与とスキル要件をもとに、給与・スキルの分析機能も備えています。説明文は中英併記で、Chrome-CDPベースの求人クローラーと位置づけられています。
詳細を見る
活用案求人スクレイパーそのものは、りゅうさんの事業にほぼ直結しません。かつ、ログイン状態の再利用と反スクレイピング回避は、利用規約違反や法的リスクを含みます。ただし、中身の発想は一般的な道具として参考になる可能性があります。ひとつは「Chrome CDPで手元のログイン済みブラウザを操作し、APIのないWebサービスから業務データを取る」方式です。たとえば、自分のアカウントで見られる予約サイトや管理画面の数字をCSV化し、月次集計に回す場面で効きます。具体的には、Chromeを `--remote-debugging-port=9222` 付きで起動し、PlaywrightやPuppeteerの `connectOverCDP` で接続する形です。もうひとつは、取得後に「JSON/CSV出力→集計・分析」まで一気通貫にする構成です。注意点として、他社サイトの規約で自動取得が禁止されている場合や、個人情報を含むデータには使わない方がよいです。クライアントへの提案に使うなら、自社アカウントの範囲に限るのが安全です。
まずリポジトリのREADME(https://github.com/eatmoreduck/boss-zhipin-scraper)を開き、CDP接続部分の説明だけ読めば十分です。手を動かすなら、PowerShellで `chrome.exe --remote-debugging-port=9222 --user-data-dir=C:\temp\cdp-test` を起動し、`http://localhost:9222/json` にタブ一覧が出るかを確認してください。スクレイピング対象は自分が権限を持つ画面だけにしましょう。
