Claude Code v2.1.314
概要Claude Code v2.1.314 で、新しい設定 `permissions.blockWritesOutsideWorkingDirectories` が追加されました。これを有効にすると、Write・Edit・NotebookEdit の3つのツールが、作業ディレクトリ(working directories)の外にあるパスへの書き込みを、どの権限モードでも拒否します。従来は、権限モードによっては作業ディレクトリ外のファイルも編集できる場合がありました。今回は、自動承認系のモードでも例外にならない書き込み範囲の上限を、設定で固定できます。
詳細を見る
活用案Claude Codeに長い作業を任せる場面で、書き込み範囲の安全柵として効く可能性があります。たとえば複数のリポジトリや `.claude` ディレクトリを `additionalDirectories` で追加している環境では、意図しない場所へ書き込まれる事故を抑えられそうです。設定は `settings.json` の `permissions` に `"blockWritesOutsideWorkingDirectories": true` を入れる形が想定されます。特に、承認を省略して連続実行させるモードや、自動実行・定期実行から呼ぶ運用と相性が良いと思います。放置しても、他プロジェクトや設定ファイルを巻き込みにくくなります。注意点として、この制限はWrite・Edit・NotebookEditが対象なので、Bashでの `echo >` や `cp` による書き込みは別の仕組み(sandboxやdenyルール)で守る必要があるかもしれません。また、共有リポジトリの外にある設定やメモリを編集させたい作業では拒否されるため、そうした作業のときだけ設定を外すか、作業ディレクトリに追加する運用が考えられます。
まず https://code.claude.com/docs/en/changelog で v2.1.314 の該当行を確認し、`permissions.blockWritesOutsideWorkingDirectories` の記載場所を権限設定のドキュメントでも探してください。次に、テスト用のプロジェクトの `.claude/settings.json` に `{"permissions": {"blockWritesOutsideWorkingDirectories": true}}` を入れます。そのうえで、作業ディレクトリ外のファイルを編集させて拒否されるか、Bash経由の書き込みは通るかを確認すると、守れる範囲が分かります。

Claude Code v2.1.316
概要Claude Code v2.1.316 のチェンジログで、環境変数 CLAUDE_CODE_DISABLE_ULTRATHINK が追加された。この変数を設定すると、プロンプト内に「ultrathink」というキーワードを書いても拡張思考(深い推論)が発動しなくなり、キーワード機能そのものがオフになる。これまでは、文中にうっかり ultrathink と含めるだけで思考量が増えていたが、その挙動を明示的に無効化できる。出典は公式ドキュメントのチェンジログ。
詳細を見る
活用案ultrathink が効いてほしくない場面で役立つ可能性があります。たとえば、Codex と Claude Code を共有リポジトリで使い、ドキュメントや議事録、ニュース記事に「ultrathink」という語がそのまま含まれていると、意図せず思考が深くなり、トークン消費や応答時間が増えることがあります。自動実行(スクリプトやcronで claude -p を呼ぶ週次処理など)で入力文に外部テキストが混ざる運用では、コストと所要時間を安定させる目的で、環境変数 CLAUDE_CODE_DISABLE_ULTRATHINK=1 を設定する手があります。設定は ~/.claude/settings.json の env に書くか、実行するシェルで export する形が考えられます。一方、対話中に「ここは深く考えて」と自分で ultrathink を使っている場合は、無効化すると使えなくなるため、常用している人には向きません。まず自動実行用の環境だけに限定して試すのが安全です。
手元で影響を確かめるなら、PowerShell で `$env:CLAUDE_CODE_DISABLE_ULTRATHINK=1; claude` と起動し、プロンプトに ultrathink を含めて思考量が変わらないか見る。常用するなら ~/.claude/settings.json の "env" に "CLAUDE_CODE_DISABLE_ULTRATHINK": "1" を追記する。詳細は https://code.claude.com/docs/en/changelog の v2.1.316 の項を参照。

MCP: Kagan
概要PulseMCPに掲載されたMCPサーバー「Kagan」は、ターミナル上で動くカンバンボード型のツールで、自律実行(autonomous)モードと、人が並走するペア(pair)モードの2種類でコーディングエージェントを動かせる。対応するエージェントプロバイダーは14種類。タスクをカード化してボードで管理しつつ、複数のエージェントに振り分けて進捗を一覧できる点が特徴で、Claude CodeやCodexのような異なるエージェントを一つの画面から束ねる「エージェント司令塔」の位置づけにある。リポジトリは gh-kagan-sh/kagan。
詳細を見る
活用案りゅうさんはCodexとClaude Codeを共有リポジトリで併用しているため、タスクごとにどのエージェントへ何を渡したかをカンバンで一元把握できる可能性があります。たとえば、QuoteBillingの小さな修正やTaskLensの改善といった独立した複数タスクをカード化し、軽い作業は自律モード、仕様判断が絡む作業はペアモードで進める、といった使い分けが考えられます。試すなら、まず使い捨てのテスト用リポジトリでKaganを起動し、既存のClaude Code・Codexを2〜3枚のカードに割り当てて、ボード上で状態が追えるかを確認する流れが無理がありません。注意点として、自律モードは複数エージェントが同じ作業ツリーを触ると衝突しやすいので、ブランチやworktreeが分離されるかを先に確認したほうがよいです。また、現在のbacklogの優先順位が固まっている中で新ツール導入を増やすと着手過多になり得るため、まずは情報収集に留めるのが安全です。
ブラウザで https://www.pulsemcp.com/servers/gh-kagan-sh/kagan を開き、対応する14プロバイダーにClaude CodeとCodexが含まれるかと、インストール方法を確認する。次に GitHub の gh-kagan-sh/kagan のREADMEで、worktree分離の有無と自律/ペアモードの切替方法の記述を読む。試す場合は、本番リポジトリではなく空のテスト用リポジトリで行う。
