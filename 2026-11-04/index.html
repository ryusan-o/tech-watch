Claude Code v2.1.317
概要Claude Code v2.1.317 の変更履歴です。/schedule コマンドに警告が追加されました。クラウド上で新しい定期実行タスク(cloud scheduled task)を作成したとき、ユーザーが指定していないコネクタ(Gmail、Slack、Notion などの外部サービス連携)が自動で付いてくる場合があります。その場合に警告が表示され、不要なコネクタの外し方も併せて案内されます。意図しない権限がスケジュール実行のタスクに紛れ込むのを防ぐ、安全面の改善です。
詳細を見る
活用案定期実行をクラウドで回すときの「権限の持ち込み」を確認する場面で効く可能性があります。たとえば、週次ニュースの要約や議事録の整形のようなルーティンを /schedule で作ると、普段つないでいるGmail、Google Drive、Slack、Notionなどのコネクタが意図せず付与されることがあります。無人で動くタスクに、メール送信やドライブ書き込みといった外向きの権限が付いたままだと、プロンプトの指示ミスや外部文章の混入で想定外の操作が起きるリスクがあります。今後は /schedule 作成時に警告が出たら、そのタスクに本当に必要なコネクタだけを残し、読み取り専用で足りるものは外す、という運用が考えられます。クライアント向けの自動化を組むときも「最小権限で渡す」説明材料になります。注意点として、警告は作成時に出るだけなので、すでに作成済みのスケジュールタスクは自動では見直されません。
Claude Code を v2.1.317 以降に更新し(claude update)、/schedule を一度実行して警告の出方を確認してください。すでに作成済みの定期タスクがある場合は /schedule の一覧で、各タスクに付いているコネクタを開き、不要なGmail・Slack・Notion等が残っていないか見直すのが最初の一歩です。詳細は https://code.claude.com/docs/en/changelog の v2.1.317 の項目に載っています。

GitHub: xerj-org/xerj
概要GitHub Trendingに登場した「xerj-org/xerj」は、AIエージェント/bot向けの検索エンジン兼MCPサーバーです。Rust製の単一バイナリで、コード、ドキュメント、ログ、JSONL/CSV、PDFをインデックス化し、BM25全文検索、ベクトル検索、ハイブリッド検索に対応します。grepを使わないコード検索、エージェントのメモリ、RAGにも使えます。APIはElasticsearch互換です。さらに「Corpus Hub」から、数百種の参照用メモリコーパスを配信するとされています。なお、上記は説明文に基づく内容で、性能や成熟度は未検証です。
詳細を見る
活用案Claude CodeやCodexを共有リポジトリで使う場面で、議事録、ログ、PDF、過去の提案書などを横断検索する「ローカル知識検索層」として試せる可能性があります。たとえば、MeetingMinutesの議事録や、クライアント向け資料のPDF/CSVをインデックス化し、MCPサーバーとして登録すれば、エージェントが「あの商談で何を決めたか」をgrepより意味検索で引ける形が考えられます。単一バイナリなのでVPSにも置きやすく、Elasticsearch互換APIなので既存ツールとつなぎやすい点も利点になりえます。手順は、READMEに沿ってバイナリを取得し、議事録フォルダだけを対象にインデックス化、.mcp.jsonに登録して検索精度をgrepと比べる、という小さな検証が向きます。注意点は、顧客情報や個人情報を含む資料を入れる場合です。Corpus Hubなど外部への通信や送信の有無を確認し、まず機密を含まない公開資料だけで試すのが安全です。新しいプロジェクトで成熟度も不明なため、本番業務への組み込みはまだ早いと思われます。
ブラウザで https://github.com/xerj-org/xerj を開き、READMEの「Install」「MCP」「Corpus Hub」の節を読んで、①外部通信の有無、②MCPの登録方法、③ライセンスの3点を確認してください。そのうえで、機密を含まない公開Markdown数十件だけをインデックスし、同じ質問をgrepと比べてみるのが最初の一歩です。

GitHub: Neywa-Labs/mlx-audio
概要Neywa-Labs/mlx-audio は、Appleの機械学習フレームワーク MLX 上に構築された音声ライブラリで、GitHub Trendingに登場した。テキスト読み上げ(TTS)、音声認識(STT)、音声から音声への変換(STS)の3機能を1つのライブラリで扱える。Apple Silicon(Mac の M シリーズ)向けに最適化されており、ローカル環境で効率よく音声解析・生成を実行することを目的としている。クラウドAPIを使わず、手元のMac上でモデルを動かす選択肢を広げる位置づけ。
詳細を見る
活用案最も関係しそうなのは議事録の文字起こし(STT)です。現在 MeetingMinutes では Whisper 系で固有名詞の誤変換が課題になっていますが、MLX 版の Whisper 系モデルをローカルで回せれば、外部APIへ音声を送らず、顧客の商談音声を手元で処理できる可能性があります。使い方の一例は、`pip install mlx-audio` で入れ、同梱のCLIやPythonサンプルで既存の会議録音1本(数分)を文字起こしし、現行の結果と固有名詞の精度・処理時間を並べて比較する形です。ただし前提としてApple Silicon搭載のMacが必要で、現在の作業環境はWindows(Windows 10 Home)のため、そのままでは動きません。Mac機を持っていない場合は導入のメリットが出にくく、VPS上の運用にも載せられません。また、TTS/STSには音声クローン機能が含まれる場合があり、顧客利用や公開に使う際は権利・同意の確認が必要です。
まず https://github.com/Neywa-Labs/mlx-audio のREADMEを開き、「対応モデル(STTにWhisper系があるか、日本語対応か)」と「動作要件(macOS / Apple Silicon限定か)」の2点だけ確認する。Macが手元にある場合のみ、短い会議音声1本で試す。Windows環境のままなら、今は見送りで問題ない。
