Claude Code v2.1.326
概要Claude Code v2.1.326のチェンジログです。agent teams(複数のエージェントをチームとして並列に動かす機能)が有効な状態でも、Code Modeをオンにできるようになりました。すでにCode Modeをオンにしている人については、teamsを有効にしたセッションは最初からCode Modeで起動します。これまでは両機能の併用に制約があったため、チーム構成で動かしつつCode Modeの挙動を使いたい場合の障壁が取り除かれた更新です。
詳細を見る
活用案CodexとClaude Codeを共有リポジトリで使い、複数タスクを並行で進める運用では、agent teamsとCode Modeを併用する場面で効く可能性があります。たとえばクライアント向けの自動化スクリプトや業務システムの改修で、実装担当とレビュー担当のエージェントを分け、全員をCode Modeで動かす使い方が考えられます。手順としては、設定画面かCLIでCode Modeを一度オンにし、agent teamsを有効にしてセッションを開くだけです。以降は自動でCode Modeで始まるので、毎回の切り替えが不要になります。一方、挙動が変わる点には注意が必要です。teams有効のセッションが自動でCode Modeになるため、これまでと違う動きに戸惑う場合があります。重要なリポジトリでいきなり使わず、小さな検証用の作業で動きを見てから広げるのが安全だと思います。
公式チェンジログ(https://code.claude.com/docs/en/changelog)のv2.1.326の項目を開き、Code Modeの有効化方法とagent teamsとの関係を確認します。その後 `claude --version` で現在のバージョンを確認し、2.1.326未満なら更新します。検証は影響の小さい作業用ディレクトリで、teams有効のセッションを起動して挙動を見るところから始められます。

GitHub: obsidianmd/obsidian-skills
概要obsidianmd/obsidian-skills は、Obsidian公式組織(obsidianmd)が公開しているGitHubリポジトリで、AIエージェント向けの「Agent Skills」集です。エージェントに、Obsidian CLIの使い方と、Markdown、Bases、JSON Canvasといったオープンなファイル形式の扱い方を教えるためのスキル定義が入っています。これにより、Claude CodeやCodexのようなエージェントが、Obsidian Vault内のノート、データベース風のビュー(Bases)、図解キャンバス(JSON Canvas)を、独自流儀ではなく正しい作法で読み書きしやすくなります。今週のGitHub trendingに入っています。
詳細を見る
活用案りゅうさんはClaude CodeとCodexを共有リポジトリで使い、`00_Brain/` のような知識ベースをMarkdownで管理しています。もしVaultをObsidianで開いている、または開く予定があれば、このスキルを導入すると、エージェントがwikilink、frontmatter、Basesの書式を崩さずにノートを追加・更新できる可能性があります。例えば議事録や技術ウォッチの結果をVaultに自動で書き出す場面で、リンク切れや書式崩れを減らす効果が見込めます。具体的には、リポジトリをcloneし、含まれるスキルのフォルダを `.claude/skills/` にコピーして、スキル一覧に出るか確認する流れが考えられます。JSON Canvasは、クライアント向けの業務フロー図やうま藻の事業構造を、エージェントに下書きさせる用途にも合いそうです。注意点として、既存のスキルやrulesと指示が重複・競合することがあるため、まず検証用のコピーで試し、既存ファイルを直接書き換えさせない運用が安全です。
ブラウザで https://github.com/obsidianmd/obsidian-skills を開き、README と各スキルの SKILL.md(CLI、Bases、JSON Canvas)を読んで、対応するエージェントとインストール方法を確認する。次に、検証用の空フォルダで `git clone https://github.com/obsidianmd/obsidian-skills` を実行し、中身のスキルを1つだけ `.claude/skills/` に置いて、Claude Codeから呼び出せるか試す。

GitHub: yazinsai/OpenOats
概要yazinsai/OpenOats は、Mac向けのミニマルな会議録音アプリ(オープンソース・無料)。「Start」を押して会議し、「Stop」を押すと、ノートと「You/Them」(自分と相手)に話者分離された文字起こしが、1つのMarkdownファイルにまとまって出力される。処理はすべてオンデバイスで完結し、音声や文字起こしを外部クラウドへ送らない設計。GitHubのtrendingに上がった。機能を絞り、録音から議事録Markdown生成までの流れを最短にしている点が特徴。
詳細を見る
活用案りゅうさんは議事録自動化(MeetingMinutes)を運用しているので、その入力側の選択肢として比較できる可能性があります。特に効くのは、クライアントとのオンライン商談や、うま藻関連の打ち合わせ直後に「議事録を1ファイルで残したい」場面です。使い方の一例として、OpenOatsで会議を録音し、出力されたMarkdown(You/Them分離済み)をClaude Codeやリポジトリのノートに置き、要約・タスク抽出だけを後段のAIに任せる、という分担が考えられます。オンデバイス処理なので、顧客の発言や経営情報を外部の文字起こしAPIへ送りたくない案件では安心材料になるかもしれません。一方で、対応はMacのみです。りゅうさんの実行環境がWindowsなら、そのままは使えません。また、You/Them の2者分離なので、3人以上の会議で話者を区別したい用途には向きません。録音自体は、相手への事前の同意確認も必要です。
まず https://github.com/yazinsai/OpenOats のREADMEを開き、対応macOSバージョン、使用している文字起こしモデル、出力Markdownのサンプルを確認してください。手元にMacがあれば、短い雑談を1本録って、出力形式がMeetingMinutesの入力として使えるかを見るのが最初の一歩です。Windowsしかない場合は、対応OSの記述だけ確認すれば十分です。
