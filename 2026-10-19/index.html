Claude Code v2.1.302
概要Claude Code v2.1.302のチェンジログで、新しい環境変数 CLAUDE_CODE_AUTO_MODE_MODEL が追加された。auto mode(権限確認を自動判定して進めるモード)では、ツール実行を許可してよいか判断する分類器(classifier)が動く。この変数は、そのうちクライアント側の分類器が使うモデルを指定するためのもの。サーバー側のauto modeで使われるモデルは変わらない。つまり、変わるのは判定役のモデルだけで、作業を担当するメインモデルには影響しない。
詳細を見る
活用案auto modeで「確認が多くて止まる」「判定が遅い」と感じる場面で効く可能性があります。たとえばCodexとClaude Codeを共有リポジトリで回していて、長いタスクを放置して進めたい時です。判定役を軽量・高速なモデルに寄せれば待ち時間やコストを抑えられ、逆に本番に近い作業(請求系の見積・請求システムやVPS操作など)では、判定を厳しめの上位モデルに固定して誤許可を減らす、という使い分けも考えられます。設定は、起動前に環境変数 CLAUDE_CODE_AUTO_MODE_MODEL にモデルIDを入れるか、settings.jsonのenvに書く形が候補です。注意点として、クライアント側の分類器にだけ効き、サーバー側auto modeには効かないため、自分の環境がどちらで動いているかを先に確認しないと「設定したのに変わらない」となり得ます。また、判定を軽いモデルにすると危険な操作の見逃しが増えうるので、破壊的操作が多いリポジトリでは慎重に試すのがよさそうです。
まず https://code.claude.com/docs/en/changelog で v2.1.302 の該当行と、auto modeの説明ページ(クライアント側/サーバー側の違い)を読む。試す場合は PowerShell で `$env:CLAUDE_CODE_AUTO_MODE_MODEL="<モデルID>"; claude` と起動し、`claude --version` で2.1.302以上であることを確認したうえで、いつもの作業での確認の出方や待ち時間を比べる。

Oct 18, 2026AnnouncementsInvesting in the public benefit
概要2026年10月18日、Anthropicは新設の「Anthropic Public Benefit Fund」に自社株の5%を拠出すると発表した(株主承認が前提)。基準となる企業価値から50%上昇するごとに、取締役会の裁量で最大2%を追加する仕組みで、既存のコミットメントを含めると最終的に約20%が公益目的になる。ファンドは100%子会社のLLCで、501(c)(3)などの非営利法人ではない。給付の自由度を確保するためで、株式は米国内外を問わずロビー活動や政治献金には使わない。用途は大手非営利団体への大型寄付や特定の人々への直接給付などで、例として労働市場への影響が挙がっている。この分野には既にEconomic Futures研究ファンドから2億ドルのコミットがある。創業者は株式の80%を寄付すると約束済みで、従業員の寄付にも会社がマッチングする制度があり、約半数が参加している。基準額、給付対象の条件、具体的な受取先、株主承認の時期は未公表。構造やガバナンスの詳細は今後数か月で出る予定。

活用案これは技術機能のニュースではなく、直接使えるものではない。ただ、りゅうさんの仕事に効く場面が2つあると思います。1つ目はAIコンサルの提案です。「AIで仕事が変わる」という話の裏づけとして、労働市場への影響にAI企業が資金を出し始めていることを、クライアントへの説明材料に使えるかもしれません。学童運営NPOのようなクライアントなら、Claudeの非営利向け割引や、今後ファンドから出る支援の可能性も話題にできます。2つ目は自社のベンダー判断です。主要AIベンダーの経営の方向性を把握しておくと、中長期でClaudeに依存する設計をするときの安心材料の一つになります。たとえば月次の振り返りで、利用サービスのニュースを一行メモする運用が考えられます。注意点は、給付の条件や対象が未公表であることです。ファンドの支援を受けられる前提で提案や計画を組むのは避け、詳細が出てから判断するのがよいと思います。
原文 https://www.anthropic.com/news/public-benefit-fund を開き、「Initial commitment」「Structure」の段落だけ読めば十分です。非営利のクライアントに話す可能性があるなら、Claudeの非営利向け割引のページ(Anthropicサイトで「Claude for Nonprofits」を検索)も確認してください。ファンドの詳細は「今後数か月」に出る予定なので、その時点でもう一度ニュースを見れば足ります。

MCP: Memory Fabric
概要PulseMCPに掲載されたMCPサーバー「Memory Fabric」(elvirafa-memory-fabric)は、AIコーディングアシスタント向けにファイルファースト・ローカルファーストの記憶を提供する。記憶の保存にベクトルDBを使わず、MarkdownとYAMLのファイルで管理する方式。埋め込みやDBの運用なしに、人間が読める形式でエージェントの記憶を持たせ、中身を直接開いて確認・編集できる設計。掲載情報にはこれ以上の仕様(提供ツール名やインストール手順)は書かれていない。
詳細を見る
活用案りゅうさんはCodexとClaude Codeを共有リポジトリで使い分けているので、モデルをまたいで同じ記憶を参照できる仕組みとして相性が良い可能性があります。Markdown/YAMLならGitで差分管理でき、AIが何を覚えているかをレビューできます。たとえば「クライアントごとの前提や決定事項」「AIが誤記しやすい固有名詞の正規形」(clients.mdで起きた人名ハルシネーションのような事故の再発防止)を記憶として持たせ、セッションをまたいで再説明する手間を減らす使い方が考えられます。まずは業務データを入れず、作業メモ程度の小さな範囲で、既存のCLAUDE.mdや自動メモリと役割が重複しないかを見る形が安全です。注意点として、記憶に顧客情報や個人情報が溜まるとそのままファイルに残るため、保存先をGit管理するなら公開範囲や除外設定を先に決める必要があります。また既に自前のメモリ運用があるなら、二重管理になるだけの恐れもあります。
まず https://www.pulsemcp.com/servers/elvirafa-memory-fabric を開き、リンク先のGitHubリポジトリのREADMEで、(1)提供ツール一覧、(2)記憶ファイルの保存先とフォーマット、(3)Claude Code/Codexへの登録方法(claude mcp add の記述例)を確認する。現在のメモリ運用と役割が被るかを読んで判断し、被らなければ試す価値ありと見なす。
