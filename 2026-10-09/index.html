Claude Code v2.1.295
概要Claude Code v2.1.295 のチェンジログで、command フックと HTTP フックに `onFailure: "block"` が追加された。従来、フックが起動できない、タイムアウトする、想定外の終了コードで終わるといった失敗時は、フックが無かったかのように処理が通り抜けていた。このオプションを指定すると、そのような失敗時に対象のアクション自体をブロックする。フックを安全確認の関門として使う場合に、フック自体の故障で関門が素通しになる穴を塞げる。
詳細を見る
活用案効くのは、フックを「ガード」として使っている場面です。たとえば PreToolUse で、本番サーバーへの ssh、`rm -rf`、外部への課金API呼び出しなどを検査するスクリプトを置いている場合、スクリプトのパス誤り、Windows/PowerShell 側の環境差、タイムアウトで落ちると、チェックなしで実行されてしまう恐れがありました。そこで settings.json の該当フックに `"onFailure": "block"` を足すと、検査できなかった時は止まる方向（フェイルクローズ）に倒せる可能性があります。VPSインフラや顧客データに触る操作、秘密情報の書き込み検知などが候補です。逆に、ログ記録や通知のような補助的フックに付けると、フックの不調だけで作業全体が止まって煩わしいので、安全系だけに絞るのがよさそうです。なお、設定の書き方はバージョンで変わりうるため、公式ドキュメントで確認してからの導入が安心です。
まず `claude --version` で v2.1.295 以上か確認し、https://code.claude.com/docs/en/changelog の該当項目と Hooks のドキュメントで `onFailure` の記載位置と対象イベントを読む。そのうえで、今 settings.json（または settings.local.json）に入れている PreToolUse の安全系フックを一覧し、どれが「失敗したら止めたい」ものかを洗い出す。

Claude Code v2.1.294
概要Claude Code v2.1.294 の変更履歴の1項目です。StopおよびSubagentStopのプロンプトフック(Claudeが止まろうとした時に、別のモデル呼び出しで「止めてよいか」を判定する仕組み)について、判定の精度が上がりました。たとえば「ビルドが壊れているなら続行して」のように、条件を指示文の形で書いたフックの解釈が改善され、Claudeが途中で早く止まってしまうことが減るとされています。フックの書き方の形式自体は変わらず、判定ロジック側の改善です。
詳細を見る
活用案Claudeに長めの作業(複数ファイルの修正やテスト修正)を任せたとき、まだ壊れたまま「できました」と止まってしまう場面で効く可能性があります。たとえば .claude/settings.json の hooks.Stop に type: "prompt" のフックを置き、「テストかビルドが失敗している、または未対応のTODOが残っているなら続行する。すべて通っていれば止まってよい」と指示文で書いておく使い方です。これまで判定が曖昧で効きが悪かった場合は、書き直さず再度試す価値があるかもしれません。SubagentStopにも同様に置けば、サブエージェントが中途半端に返ってくるのも抑えられる可能性があります。注意点として、判定のたびにモデル呼び出しが増えるため、応答時間とコストが少し上がります。また条件が緩いと止まらずに延々と続行するループになりうるので、「最大何回まで」などの終了条件も文中に入れておくと安心です。
すでにStopフックを設定している場合は、ターミナルで `claude update` を実行して v2.1.294 以降にし、`/hooks` コマンドで現在の設定を確認してください。未設定なら、変更履歴(https://code.claude.com/docs/en/changelog)と Hooks ドキュメントの「prompt-based hooks」の節を読み、次の長めの作業で試せば十分です。
